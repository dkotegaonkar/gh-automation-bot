## Tools and how the work was split

- **Claude Code** (Claude Opus 5.5) in VS Code wrote most of the code and ran most commands: scaffolding,
  builds, tests, local end-to-end checks, CI runs, SSH to the server, and small AWS changes and checks.
- Context files, exactly as used:
  - [`CLAUDE.md`](CLAUDE.md): project invariants, toolchain gotchas, deployment facts. It was updated
    as we learned things.
  - `apps/web/AGENTS.md` / `apps/web/CLAUDE.md`: generated by Next.js 16; they tell agents to read the
    bundled Next docs instead of relying on memory.
- **My part:**
  - Stack and infrastructure choices.
  - All account setup (GitHub App, AWS, Neon, Vercel, Slack, Groq, domain).
  - Keeping secrets out of the chat: keys went straight into `.env` or `gh secret set`, and the AI
    generated secrets directly into files.
  - Reviewing the plan and testing the live flow.
- **The AI's part:** implementation, and verifying each step before moving on, e.g. forged, duplicate
  and oversized webhooks locally, the outbox sweeper with SQS deliberately broken, and a
  prompt-injection test against Groq.

## Decisions I made

1. **AWS (EC2 + SQS) instead of Render + a Postgres queue.** The AI suggested Render and pg-boss.
   I wanted a real queue with a dead-letter queue and an always-on host, since Render's free tier sleeps
   and GitHub stops waiting after 10s. I accepted the trade-off (my own AWS account) and kept everything
   within the free tier.
2. **GitHub App sign-in instead of Cognito.** I first asked for Cognito. The AI pointed out that GitHub
   isn't an OIDC provider, so Cognito would need a self-hosted OIDC wrapper and still wouldn't give us
   the GitHub token we need to list installations. I dropped it. The GitHub App handles sign-in,
   webhooks and bot identity.
3. **No open SSH port.** CI failed because port 22 only allowed my IP. Instead of opening it to the
   world, I reused a pattern from another project: an IAM user whose only permission is editing one
   security group, so CI adds its runner IP for the length of the deploy and always removes it.
4. **Free-tier accounts only.** When I pasted an xAI (Grok) key by mistake, the AI caught the `xai-`
   prefix and refused to use it because it's a paid API. I switched to a Groq key.

## The hardest bug: tests that only passed on my machine

After Phase 1 was pushed, CI failed with *"Invalid environment configuration: WEB_URL … undefined"*
in a unit test. The AI traced it to `logger.spec.ts` importing `logger.module.ts`, which imports
`ConfigModule.forRoot()`, and that **validates the environment at import time**. Locally it passed
because `forRoot()` silently reads `./.env`, which only existed on my machine.

**What it got wrong:** it fixed the symptom by moving the function under test into a pure file and
checking that test with `.env` moved aside. One phase later, the same failure came back from
`secret-box.spec.ts`, because the new service imported `AppConfig` from the same module file.

**How it was fixed properly the second time:**
- `AppConfig` moved to a side-effect-free file (`config/app-config.ts`) that all services import.
- The config module now uses `ignoreEnvFile: true`, so nothing reads `.env` implicitly. Dev uses
  `node --env-file`, production uses Compose `env_file`.
- The rule was written into `CLAUDE.md`, and later phases ran their tests with `.env` hidden before pushing.

**Lesson:** "passes locally" was false confidence, because the local environment had state CI didn't.
The first fix should have asked why the environment differed, not why that one test failed.

**Runner-up:** GitHub's webhook delivery IDs are larger than 2^53. `JSON.parse` silently rounded
`3844943234996371456` to `…500`, and the redeliver call returned 404. The reconciler now quotes IDs
before parsing, and there's a test showing the rounding.

Other smaller wrong turns that were caught by verifying:
- The Nest CLI crashes on Node 22.14, so the build uses plain `tsc`.
- Let's Encrypt refuses `*.amazonaws.com` hostnames. This was tested, which is why I got my own domain.
- The Groq model name from memory (`llama-3.3-70b-versatile`) no longer exists; the AI listed the
  available models and switched to `openai/gpt-oss-120b`.
- A deploy failed with a full disk because `docker image prune -f` never removes SHA-tagged images.
